# Правила работы с проектом linkpc

## 1. Осознанный запуск проверок и сборок (Экономия времени и токенов)
- **НЕ запускать** автоматически и вслепую `flutter test`, `flutter analyze` или тестовые сборки (`flutter build apk`, `./gradlew assembleRelease` и т.д.) при рутинных, точечных или визуальных правках.
- Запускать тесты, анализ или компиляцию **только осознанно**:
  1. Если пользователь явно запросил запуск тестов/проверки/сборки.
  2. Если были внесены масштабные архитектурные или низкоуровневые изменения, несущие реальный риск поломки.
- Проверять код локально: внимательный визуальный контроль, точечные правки и `git diff`.
- Не тратить время и токены пользователя на избыточные фоновые ожидания.

## 2. Подготовка версий и Git-тегов
- При завершении задачи всегда повышать версию в `pubspec.yaml` и `lib/core/constants/app_constants.dart`.
- Создавать коммит и соответствующий Git-тег (`vX.Y.Z`).
- В итоговом ответе всегда предоставлять готовую команду для отправки:
  `git push origin <branch> && git push origin <tag>`.

## 3. Коммуникация
- Общаться на русском языке, кратко и по делу, без избыточных оправданий.
- Использовать ссылки на файлы в формате GitHub Flavored Markdown со схемой `file://`.
